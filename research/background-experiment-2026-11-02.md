# Background-removal experiment — November 2, 2026

Status: built and locally tested. User explicitly approved publication on November 2, 2026, provided it stays a separate page and does not affect the main editing features. Publication verification follows deployment.

Purpose: validate local background replacement on the owner's actual iPhone and portrait before editor integration. Route after publication: https://zyzgerry.github.io/id-photo-for-me/src/background-experiment/ .

MediaPipe Tasks Vision 0.10.21, CPU in a classic worker, explicit OffscreenCanvas/WebGL2. A: SelfieSegmenter square float16 v1, 249,537 bytes. B: SelfieMulticlass 256 float32 v1, 16,371,837 bytes. Shared SIMD runtime: bundle 137,735 bytes; loader 204,284; WASM 9,574,032. Non-SIMD fallback loader 204,137 and WASM 9,448,638 also hosted; only the selected variant is requested. Typical first use about 10.2 MB for A or 26.3 MB for B before HTTP compression, excluding the optional HEIC decoder. Both are segmentation models, not dedicated hair-matting models. B is not assumed superior.

Runtime and models are unmodified, pinned and self-hosted. Apache 2.0 confirmed from package metadata and Google model cards; NOTICE.txt records sources, license evidence, sizes and SHA-256 hashes. The newest runtime 1.2.0 documents metrics telemetry and was not adopted. Version 0.10.21 is pinned, with same-origin-only CSP connections. No analytics or image uploads are part of this experiment.

Reuses existing photo loader: orientation, HEIC, 30 MB/50MP/12000-side source limits and 4096 working longest edge. Original and results remain in memory. Failed replacements preserve prior source/results. Cancel terminates inference worker; generation checks discard obsolete decode/PNG work. Models only load after Run. No production editor, crop, adjustments, requirements, JPEG or 600-PPI export code changed. The local development server gained correct .mjs/.wasm MIME types.

UI: select photo; run A then B; inspect original and both results; open full-size images in Safari for zoom; save PNG; repeat a model; download JSON measurements. Report includes browser, working dimensions, preparation/download/inference/composite timings and optional device/notes. No photo or filename included; no report upload. English-only experiment. Model download progress counts decoded bytes; preparation includes other downloads and initialization. Browser resource encoded/transfer bytes can be zero or cache-derived. Inference timing includes mask extraction. End-to-end time includes image transfer, compositing and PNG encoding. No offline or passport acceptance claim.

Local evidence: all 18 existing Node checks pass. All four focused Chrome/Windows-WebKit scenarios pass. Chrome runs actual A, B and repeated B, validates reuse, output PNG dimensions/opacity, no model download before activation, local GET/blob requests only, filename-free report, failed-replacement recovery, clear and phone-width layout. Both engines test cancel during blocked model download. Windows WebKit lacks OffscreenCanvas: its inference scenario verifies recoverable unavailability, not real-model inference. Synthetic 600x800 art tests plumbing only, not quality. Phone screenshot visually inspected. Local Chrome times are not phone/cold-network benchmarks.

Design inherits existing navy/blue and pale-background system-font controls. Mechanical detector only warns about the intentionally sourceless original image hidden until photo selection. No placeholder image ships. Exact source and private photos are never committed.
